## 1. 设计概述

本系统采用「微信小程序前端 + 微信云开发（CloudBase）后端」的轻后端架构：

- 前端：微信小程序原生框架（WXML / WXSS / JS），承担拍照上传、校对编辑、错题集展示。
- 后端：云函数 + 云数据库 + 云存储，承担登录态、OCR 调用、联网搜题、数据隔离与权限控制。
- 第三方：OCR 服务、搜题 / 大模型服务。

选择云开发的原因：免运维、天然打通微信登录（openid）、存储与数据库开箱即用、无域名备案负担，适合 MVP 快速落地。

## 3. 技术选型

| 模块 | 推荐方案 | 备选方案 | 说明 |
| --- | --- | --- | --- |
| 前端框架 | 微信小程序原生框架 | uni-app / Taro | 原生最贴合平台能力，MVP 首选 |
| 后端 | 微信云开发（云函数 / 云数据库 / 云存储） | 自建 Node 后端 + 云服务器 | 云开发免运维、打通登录 |
| OCR | 腾讯云 OCR（通用印刷体 + 手写体）【待确认】 | 百度 OCR、微信服务市场第三方 | 印刷题 + 手写题均需覆盖 |
| 联网搜题 | 云函数调用大模型 API（支持联网检索，如 DeepSeek / 通义 / 豆包等）【待确认】 | 第三方题库 API（多为付费/封闭，需商务合作） | 大模型可同时产出答案与解题思路 |
| 图片压缩 | 前端 Canvas 压缩 + 云函数二次处理 | 仅前端压缩 | 控制流量与 OCR 成本 |
| 云函数运行时 | Node.js | — | 与云开发原生集成 |

## 6. API / 云函数设计

统一返回结构：

```json
{ "code": 0, "message": "ok", "data": {} }
```

### 6.1 login

- 入参：无（`cloud.getWXContext()` 取 openid）
- 返回：`{ openid, userInfo }`

### 6.2 ocrParse

- 入参：`{ fileId: string }`
- 出参：`{ question, answer, solution, hasAnswer, rawText }`
- 内部：校验 fileID 归属 → 调用 OCR 服务 → 用提示词让大模型做结构化抽取 → 返回。

### 6.3 enrichAnswer

- 入参：`{ question, hasAnswer, answer?, solution? }`
- 出参：`{ answer, solution, source }`
- 内部：`hasAnswer == false` 时联网搜题；有答案时仅补思路。

### 6.4 saveMistake

- 入参：`{ setId, imageFileId, question, answer, solution, answerSource, subject, grade, tags }`
- 出参：`{ mistakeId }`
- 支持新增与更新（带 `_id` 即更新）。

### 6.5 mistakeSet

- 入参：`{ action: 'create'|'rename'|'delete'|'list', ... }`
- create：`{ title, grade, subject }`
- delete：需校验该错题集下无错题或级联软删。

### 6.6 listMistakes

- 入参：`{ setId?, keyword?, subject?, mastery?, page, pageSize }`
- 出参：`{ list, total, hasMore }`

### 6.7 getFileUrl

- 入参：`{ fileId }`
- 出参：`{ tempUrl }`（云存储临时链接，带有效期）

## 7. 核心流程设计

### 7.1 错题录入与 OCR 解析

```text
用户选择图片
   │
   ▼
前端压缩 → 上传云存储（私有读）→ 获得 fileID
   │
   ▼
调用云函数 ocrParse(fileID)
   │
   ├─ 校验 fileID 属于当前用户
   ├─ 调用 OCR 服务识别文字
   ├─ 大模型结构化：题干 / 答案 / 过程 / hasAnswer
   ▼
返回校对页数据 → 用户编辑确认
   │
   ▼
若 hasAnswer=false → 前端提示「自动补答案」→ 调 enrichAnswer
   │
   ▼
用户确认 → 调 saveMistake 入库
```

### 7.2 答案补齐（联网搜题）

```text
enrichAnswer 收到 { question, hasAnswer }
   │
   ├─ hasAnswer=true  → 仅用大模型补「解题思路」
   ▼
hasAnswer=false
   │
   ▼
大模型 API（联网检索模式）：
   输入题干 → 检索 → 生成 { answer, solution, source }
   │
   ├─ 成功：返回结果，source = "ai/web"
   ├─ 无结果/超时：返回 code 提示「未找到，可手动录入」
   ▼
前端进入编辑态，用户可修改后保存
```

> 关键点：前端不直接访问搜索接口，全部在云函数内完成，避免暴露密钥、绕过域名白名单限制，也便于统一配额与审计。

## 9. 前端状态管理

- 使用 `globalData` 存储登录态、当前错题集上下文，避免过度设计。
- 若页面间共享数据增多，可引入轻量状态方案（如 mobx-miniprogram）【P1 再评估】。
- 云存储图片使用临时 URL 并做本地缓存（`wx.getImageInfo` / file 缓存），减少重复拉取。

## 10. 安全设计

1. 所有云函数内以 `cloud.getWXContext().OPENID` 为信任根，禁止前端传 openid。
2. 数据库权限：集合默认「仅创建者可读写」；写操作尽量收敛到云函数，避免直接客户端写库。
3. 云存储：图片私有读，通过 `getFileUrl` 返回限时临时链接。
4. 密钥管理：OCR、大模型密钥仅存于云函数环境变量，不下发前端。
5. 隐私合规：首次使用展示隐私政策并获取授权，明确图片与识别内容用途。
6. 内容安全：对自动生成内容做基本过滤，避免敏感 / 违规内容展示。

## 11. 异常与边界处理

| 场景 | 处理 |
| --- | --- |
| 图片过大 | 前端压缩 + 限制单张 ≤ 10MB 原图，压缩后 ≤ 1MB |
| OCR 无文字 / 识别失败 | 提示「未识别到内容」，允许重试或手动录入 |
| 搜题无结果 | 提示「未找到答案，可手动录入」，不阻塞保存 |
| 第三方服务超时 | 15s 超时，返回可重试状态 |
| 网络异常 | 全局统一 toast，保存前内容本地暂存，防止丢失 |
| 错题集被删除 | 级联软删其下错题，列表过滤 status=deleted |

## 12. 部署与环境配置

- 环境：微信云开发新建环境（建议测试 / 生产两套）。
- 云函数：按模块部署，配置超时时间（enrichAnswer 建议 ≥ 20s）、环境变量。
- 域名 / 服务：云函数调用第三方服务走云函数出口，无需额外域名备案。
- 发布：小程序后台配置隐私协议、类目、提审材料。
