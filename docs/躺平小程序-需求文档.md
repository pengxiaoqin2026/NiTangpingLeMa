## 1. 项目概述

### 1.1 背景

「躺平」「牛马」是当下年轻人对工作与生活压力的自嘲表达。很多用户想知道：在某座城市，一个月要花多少钱才能维持生活？要实现「躺平」（被动收入覆盖开支）需要多少本金？以自己现在的存款和工资，还要工作多久？这些是真实存在的计算需求，但目前缺少一个把「城市生活成本 + 财务测算 + 幽默表达」串起来的轻量工具。

### 1.2 产品目标

1. 用户选择省份、城市，系统估算该城市的月生活费。
2. 根据月生活费反推「躺平所需本金」。
3. 用户输入存款、工资等，计算「还需当多久牛马」。
4. 生成一份语言诙谐的「牛马报告」，支持分享。

### 1.3 产品定位

- 定位：一款娱乐化的生活测算 / 财务规划小工具，结果是「娱乐参考」，不构成理财建议。
- 本期范围（MVP）：选城市 → 估生活费 → 算躺平本金 → 算牛马年限 → 生成报告 → 分享。
- 非本期范围：多方案对比、资产配置建议、理财课程、社交社区、账号体系深度运营。

## 2. 目标用户与使用场景

### 2.1 用户画像

| 角色 | 特征 | 诉求 |
| --- | --- | --- |
| 上班族 / 年轻人 | 20~35 岁，关注攒钱与躺平话题 | 想知道自己离躺平有多远，寻求共鸣与娱乐 |
| 准毕业生 / 求职者 | 正在选城市 | 对比不同城市的生活成本与「躺平门槛」 |
| 围观用户 | 被「牛马报告」传播吸引 | 娱乐化参与，顺手分享 |

### 2.2 核心使用场景

1. 场景 A：用户选了「广东 - 深圳」，看到月生活费估算，输入存款 20 万、月薪 1.5 万，得出「还需当 12 年牛马」，生成报告分享到朋友圈。
2. 场景 B：求职者对比「长沙」和「北京」，看哪座城市躺平门槛更低。
3. 场景 C：用户工资低于当地生活费，报告用幽默方式给出「换个城市 / 加薪」建议。

## 3. 功能需求

### 3.1 功能总览

核心链路：选择省份城市 → 估算月生活费 → 计算躺平本金 → 输入存款工资 → 计算牛马年限 → 生成并分享牛马报告。

### 3.2 功能详细说明

#### F1 省份 / 城市选择

- 使用微信原生区域选择器（省 → 市，暂不含区县）。
- 支持城市搜索 / 常用城市快捷入口（可选 P1）。
- 选择后进入生活费估算。

#### F2 城市生活费估算（大模型）

- 调用大模型估算该城市单人月生活费，输出分项与合计，建议分项包括：房租、餐饮、交通、水电通讯、日用品、娱乐社交、医疗应急。
- 估算结果附「仅供参考」提示，允许用户手动微调各分项金额。
- 对常见城市做结果缓存，降低重复调用与成本。

#### F3 躺平本金计算

- 依据「月生活费 × 12 / 年化收益率」计算躺平所需本金（默认年化 4%，可调）。
- 展示公式与输入参数，让用户理解「为什么是这么多钱」。

#### F4 牛马年限计算

- 用户输入：当前存款、月工资（税后到手）；可选：每月强制储蓄额、自定义年化收益率。
- 计算逻辑：每月可储蓄 = 工资 − 生活费；在存款与每月追加储蓄按复利增长的条件下，求解资产达到躺平本金所需时长。
- 输出：还需多少年 / 个月，以及到站时的目标资产。
- 边界处理：
  - 工资 ≤ 生活费：显示「月月光 / 入不敷出」，给出幽默化建议，不输出负年限。
  - 存款已 ≥ 躺平本金：显示「已可躺平」。

#### F5 牛马报告生成（大模型）

- 输入大模型的信息仅包含：城市、月生活费、躺平本金、牛马年限、可选昵称，不包含精确存款与工资数字（隐私隔离）。
- 大模型生成一段诙谐、自嘲风格的个人报告，包含：城市生活画像、躺平门槛、牛马倒计时、一句收尾金句。
- 文案风格要求：轻松、有梗、不低俗、不含政治敏感或人身攻击内容。

#### F6 报告分享与历史（P1 可选）

- 生成可保存 / 分享的报告卡片（图片海报）。
- 最近测算记录本地保存（不强制登录）。

### 3.3 功能优先级

| 优先级 | 功能 |
| --- | --- |
| P0（MVP 必做） | F1 选城市、F2 估生活费、F3 躺平本金、F4 牛马年限、F5 生成报告 |
| P1（可做） | F6 报告海报分享、常用城市、测算历史 |
| P2（暂不做） | 账号体系、社区、多方案对比、理财内容 |

## 4. 核心计算规则与假设（审核重点）

### 4.1 躺平本金

躺平本金 A = 月生活费 M × 12 ÷ 年化收益率 r

- 默认 r = 4%（参考 FIRE 4% 法则），即约等于「月生活费 × 300」。
- 示例：月生活费 6000 元 → 躺平本金 ≈ 6000 × 300 = 180 万元。
- 【待确认】默认收益率是否固定 4%，以及是否提供 2% / 3% / 4% / 6% 档位。

### 4.2 牛马年限

每月可储蓄 S = max(0, 月工资 W − 月生活费 M)

资产按月复利增长，月利率 i = r / 12

求解满足以下等式的月数 T：

D × (1+i)^T + S × [ (1+i)^T − 1 ] ÷ i = A

- D 为当前存款，W 为税后月工资，A 为躺平本金。
- 若 S = 0 且 D < A：视为无法靠当前收入攒够，报告给出替代建议，不显示具体年限。
- 若 D ≥ A：T = 0，显示已可躺平。
- 结果向下取整到月，并换算为「X 年 Y 个月」。

### 4.3 关键假设

- 单人生活成本，不含房贷 / 车贷 / 育儿等大额支出，报告中需说明。
- 生活费与工资在测算期内保持不变（未考虑通胀与加薪）。
- 收益率不构成收益承诺，展示免责声明。

## 6. 非功能需求

### 6.1 性能

- 生活费估算（含大模型调用）目标 ≤ 10 秒，需加载态与超时提示。
- 报告生成目标 ≤ 10 秒。
- 首次进入、城市选择、结果展示无卡顿，首屏 ≤ 3 秒。

### 6.2 合规与内容安全

- 结论明确标注「娱乐测算，仅供参考，不构成任何投资理财建议」。
- 报告话术通过内容安全过滤，避开低俗、政治敏感、人身攻击表达；「牛马」等自嘲词控制在幽默尺度内。
- 隐私：存款、工资仅用于本地计算与报告所必需的最少字段，默认不上传精确数值；如涉及上传需明确告知并取得同意。
- 遵守微信小程序运营规范，类目建议选择「工具-效率」或「生活服务」类【待确认】。

### 6.3 可用性与兼容性

- 支持 iOS / Android 主流机型与常见微信基础库。
- 输入校验：存款、工资需为非负数字，异常输入友好提示。

## 7. 约束与假设

- 假设：大模型可稳定调用，且其城市生活成本数据可用；估算值不保证与真实消费完全一致。
- 假设：用户理解结果为娱乐参考。
- 约束：小程序包体与域名白名单符合微信要求，大模型调用在云函数侧完成。
- 约束：不提供投资建议、不承诺收益。

## 8. 验收标准

1. 可完成「选城市 → 生活费 → 躺平本金 → 牛马年限 → 报告」完整闭环。
2. 躺平本金与牛马年限公式实现正确，边界（工资≤生活费、存款≥本金）处理正确。
3. 报告文案诙谐、合规、不泄露精确收入数据。
4. 页面在常见机型流畅运行，无白屏与未捕获异常。
5. 所有页面有明确「娱乐参考」免责声明。
6. 报告可分享（P1 项为海报，MVP 至少支持文字复制 / 截图分享）。
